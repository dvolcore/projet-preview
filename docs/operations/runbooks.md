# Production runbooks (not active monitors)

Assign an operator and backup before activation. Keep private alert destinations and provider consoles outside this repository. Written checks are not running monitoring.

## Lead or integration failure

Detect missing durable receipt, growing unassigned queue, or CRM/source reconciliation mismatch. Alert designated operator, disable misleading success/booking promises, preserve request IDs and queued data, use approved human fallback. Diagnose provider availability/authentication/mapping; retry only recoverable events with original keys. Verify one lead/owner before reopening. Never silently discard inquiries.

## Scheduling or AI failure

On capacity conflict, unknown price, urgent flooding, disputed diagnosis, injection attempt, tool outage or request for private records: stop automated commitment and transfer to assigned human. Keep transcript access restricted. Disable affected tool/automation if unresolved. Check concurrent reservation safety and owner-approved facts before resuming. No unsafe technical diagnosis by chatbot.

## Payments and reports

On mismatched invoice/payment state, pause automated collection/follow-up, reconcile provider settlement against invoice and accounting ledger, ask finance owner to resolve exceptions. Never automatically refund or retry charges beyond approved limits. On report/media access issue revoke the share, preserve originals, notify privacy operator, verify wrong-user denial and technician approval before restoring.

## SEO launch and rollback

Run independent SEO checks, then review actual release evidence. Deploy only approved domain/facts; verify HTTPS, canonical URLs, robots, sitemap, redirect chains, real 404 response and supported device flows on the live host. Submit to verified search accounts after rollout. Retain last good build and redirects; rollback by restoring artifact/config rather than editing live customer records. Avoid noindex/robots left on production. No nationwide or local ranking claim without measured query/location/date evidence.

## Continuity and maintenance

Operator chooses response targets and alert thresholds before pilot. Monitor intake availability without generating customer leads; inspect oldest failure/assignment age and reconcile counts daily during pilot. Test restore, permission revocation, secret rotation and rollback periodically and after provider changes. Review consent suppression before any follow-up replay. Capacity and acquisition budgets remain owner-controlled.

## Automation rollout

Sandbox → controlled recipients → limited production pilot → observed expansion. Require evidence of successful and failed journeys, staffed takeover and rollback at each boundary. Allowed draft tasks: summaries, missing-field checks, report drafts, suggested follow-ups, dashboard explanations. Allowed state changes require explicit approved policy and trusted tools. Maintain an audit trail of actor, input references, action, result and human approval where required. No unrestricted self-modifying price book, commitments, spend or access policy.
